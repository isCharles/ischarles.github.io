WHY I BUILT IT

记录很多，
不等于真的准备好了。

一次面试后，纪要往往躺在文档里，薄弱点留在聊天记录里，复习计划又写在另一个工具里。下一次准备，仍然要重新整理。

Ardor 尝试把这些环节连起来：保存可靠的面试纪要，整理问题与反馈，把薄弱点带入学习和练习，再回到问题本身。

面试记录→识别薄弱点→学习与重答→持续复习

BEHIND THE INTERFACE

不止调用模型，

01 / BOUNDARIES

业务状态有自己的归属

求职、学习、资料、助手与日程采用模块化单体组织。手动操作和 Agent 工具复用应用服务，不让模型直接操作数据库。

02 / EXECUTION

慢任务，不把界面锁住

生成与评估使用持久化任务，区分消息、运行和结果。支持查看任务状态、取消与追加引导；停止不冒充回滚。

03 / TRUST

行动可追踪，删除需确认

资源按用户归属校验。删除先展示真实目标，用户确认后才执行；模型和外部资料不能替代用户授权。

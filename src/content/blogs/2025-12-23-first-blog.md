## 为什么现在开始写

我并不是一个“已经很厉害”的程序员。  
相反，我目前仍然处在一个**不断补基础、补理解、补工程经验**的阶段。

但正是因为如此，我决定开始写技术博客。

原因很简单：  
**如果我不能把自己刚学到的东西讲清楚，那我大概率也没有真正理解它。**

写博客，对我来说不是展示，而是一种检验。

---

## 我不打算在这里做什么

在开始之前，我想先说清楚几件事我**不会**做的事情：

- 不会假装自己是专家  
- 不会动辄“深入源码”“工业级架构”  
- 不会为了显得高级而堆砌名词  

这不是一个“输出结论”的博客，而是一个**记录理解过程的地方**。

---

## 我打算写什么

这个博客主要会包含三类内容：

### 1. 学习笔记（Learning Notes）
- Java / 后端基础
- 算法与数据结构
- 操作系统、计算机网络中我真正卡住过的点

我更关注：
- 我一开始是怎么理解错的
- 哪个地方让我突然想通
- 如果重新学一遍，我会怎么学

---

### 2. 问题复盘（Problem Solving）
- 一道题我是如何一步步拆解的
- 一个 bug 我是怎么定位、怎么修的
- 一个设计选择为什么当时选 A 而不是 B

结果并不重要，**过程更重要**。

---

### 3. 零散思考（Notes）
一些短的记录，比如：
- 今天终于理解了 DFS 的状态定义
- 为什么我现在更偏向用 GitHub Pages 而不是博客平台
- 学技术过程中，对“工程”和“学习方法”的反思

这些可能不完整，但都是真实发生的。

---

## 为什么选择 GitHub Pages

我最终把博客放在 GitHub Pages 上，而不是博客平台，原因有几个：

- 这是一个**纯静态站点**，没有后端、没有数据库，足够简单
- 所有内容都用 Markdown 管理，有完整的版本历史
- 写作和发布本身就是一次工程流程（commit / push / deploy）

对我来说，这种方式更接近“工程实践”，而不是“内容平台”。

---

## 写给未来的自己，也写给读到这里的人

如果你读到这里，恰好也处在一个：
- 学了不少，但总觉得不扎实
- 想进步，又有点焦虑
- 想输出，又怕“写得不够好”

那你并不孤单。

这个博客并不承诺高密度干货，但它承诺一件事：

> **所有内容都来自真实学习过程，而不是事后包装。**

如果哪一天我回头看这些文章，能清楚地看到自己是如何一步步走过来的，那这件事本身就已经值得了。

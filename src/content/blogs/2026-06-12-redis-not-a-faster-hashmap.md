这篇是从之前的零散笔记里整理出来的。现在回头看，我一开始对 Redis 的理解其实很偷懒：它快，它在内存里，它能存 key-value，所以我就把它当成一个更快的 HashMap。

这个理解不能说完全错，但很容易把人带偏。HashMap 是一个进程内部的数据结构，Redis 是一个独立的服务。它有网络开销，有序列化成本，有持久化策略，有淘汰策略，也有连接数和线程模型的问题。

后来我才慢慢意识到，用 Redis 不是“把数据库查出来的数据塞进去”这么简单。真正要想的是：

- 这个 key 怎么设计，查的时候好不好定位
- value 要不要冗余一点信息，减少回表
- 过期时间是不是会集中失效
- 数据不一致的时候业务能不能接受
- Redis 挂掉以后系统还能不能降级

最典型的例子是缓存穿透、击穿、雪崩。刚学的时候我会背概念，甚至能把布隆过滤器、互斥锁、逻辑过期这些方案说出来。但背得出来和真的知道什么时候该用，差距还是很大。

我现在更愿意把 Redis 当成“系统里一个需要被设计的组件”，而不是一个随手调用的工具类。这个心态变化挺重要的。
